# ADR 0008 — Guid v7 como chave primária

Status: Aceita · Data: 2026-09

## Contexto

Chaves precisam ser geradas na aplicação (o agregado registra eventos com seu Id antes do `INSERT` e o endpoint devolve `Location` no 201), únicas entre módulos e bancos (facilita extração e merges), e amigáveis a índices B-tree. Guid v4 aleatório fragmenta índices; inteiros sequenciais exigem ida ao banco e expõem contagem.

## Decisão

`EntidadeBase.Id = Guid.CreateVersion7()` (UUID v7, RFC 9562: timestamp em milissegundos nos bits altos + aleatoriedade), coluna `uuid`, `ValueGeneratedNever()`. Vale para todas as entidades principais, para `OutboxMessage.Id` e `IntegrationEvent.Id`. Tabelas do Identity usam `Guid` também (`IdentityUser<Guid>`), gerado do mesmo modo.

## Consequências

Positivas:

- inserções quase sequenciais no índice da PK (menos page splits que v4);
- Id conhecido antes de persistir: eventos de integração, `Location`, idempotência;
- ordenação aproximada por criação sem depender de `CriadoEm`;
- globalmente único: mover dados entre schemas/bancos não colide.

Negativas:

- 16 bytes por chave e por FK (vs 8 de `bigint`); aceitável para o volume;
- o timestamp embutido revela o instante de criação (não é segredo neste domínio);
- v7 exige .NET 9+ (`Guid.CreateVersion7`) e PostgreSQL trata como `uuid` opaco (sem função nativa de geração v7 até a versão 18; a aplicação gera).

## Alternativas consideradas

- **Guid v4**: fragmentação de índice; descartado.
- **`bigint` identity/sequence**: exige round-trip para obter o Id, expõe volume, colide entre bancos; descartado.
- **ULID / Snowflake**: equivalentes, mas sem suporte nativo no .NET e no tipo `uuid`; v7 é padrão e nativo.
